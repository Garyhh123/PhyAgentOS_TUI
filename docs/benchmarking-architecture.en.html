PhyAgentOS Benchmarking Architecture

Benchmarking is an Agent workflow skill that discovers tasks, creates standard Runtime Sessions, and aggregates immutable execution evidence.

中文

1 · Boundary

Benchmarking Agent Skill

Selects an exact enabled Target, execution mode, and matching SkillRuntime tuple; appends Sessions, aggregates evidence, and writes a report.

Selected SkillRuntime

A policy runtime owns the standard observation-policy-action loop. A benchmark-specific builtin may own a typed target-native suite loop. Neither orchestrates the experiment report.

Benchmarking does not create a new SKILLRUNTIME entry, instantiate SessionRunner, or call raw Target benchmark RPCs directly.

2 · Availability Gate

runtime enabled → enabled simulation Target → declared benchmark capability → exact execution-mode/SkillRuntime match → skill visible

SkillsLoader controls skill visibility; capability matching and Runtime Preflight still validate every Session.

3 · Lifecycle

Load protocol → Select Target/mode/SkillRuntime tuple → Preserve seed, control, cadence, and retry instruction mode → Append pending Sessions → Watchdog execution → Canonical artifacts → Aggregate report

4 · Evidence

SESSIONS.md

Root Session state, routing, execution settings, score summaries, artifact references, and errors.

LOG.md

Session-indexed execution history.

Canonical artifacts

Policy-loop episode evidence or target-native benchmark manifests with episode, attempt, verifier, and failure records.

5 · Report Contract

Reports identify setup, suite/task source, seed, control mode, policy refresh cadence, recovery instruction mode, metrics, official first-attempt and assisted-final scores, verifier budget, failures, artifact paths, and comparison scope. Reports reference canonical evidence without rewriting it.
